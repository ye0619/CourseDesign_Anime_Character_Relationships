# 已审核来源别名与检索（2026-10-22）

本轮继续落实修改计划T08的“中文名、原名、别名保留出处和修订”及新来源检索联动。已交付维护、检索、来源展示和撤回失效流程；没有把标题候选自动变成别名，也没有新增真实外站已审核名称。

## 使用与行为

在[身份核验页](http://127.0.0.1:5173/maintenance/identities)选择一条**已审核**身份，在“已审核来源的检索别名”填写名称、语言、该名称的来源依据及保存理由。来源链接、修订、许可与稳定实体编号取自当前身份。每条身份最多20个名称；支持简体中文、繁体中文、日语、英语及未确定语言。名称不能为空、含控制字符或在规范化后重复。保存空列表表示明确清除当前名称。

新增两个既有权限范围内的操作：`GET /admin/external-identities/{id}/names`读取当前/失效名称，`PUT`按`expectedVersion`替换名称。维护配置仍默认关闭；启用后要求现有ADMIN会话，写入要求CSRF，维护者来自会话。保存名称同时递增身份版本；旧表单返回409、清空并要求重新选择，不自动重试。

| 入口 | 联动行为 |
|---|---|
| 本地作品、人员、角色档案检索 | 当前有效别名命中对应UID，沿用来源/年份/形式/启用状态筛选和准确分页；同名实体分别返回 |
| 在线角色/制作图谱与关系节点 | 在响应时补充当前别名与出处，节点查找可用；不改变显示名、原名或关系 |
| 配音与制作名册 | 人员及角色资料补充当前别名，复用已加载名册搜索 |
| 世界观与系列网络 | 中文名、原名及别名均可检索；选中角色显示来源修订、引用依据、许可和身份版本 |
| 本地角色关系图谱与档案详情 | 补充名称断言；档案详情可展开核对来源 |

公开名称断言使用`REVIEWED_ALIAS`，保留来源编号、来源链接、修订、语言、核验日期、依据、许可及身份版本。既有“结束乐队”项目首选名和Bangumi原始名称不被重写。

## 撤回、重开及改绑

V8增加`external_identity_name`，以身份ID和序号为键，保存名称事实及来源快照。每次保存绑定**该次递增后的身份版本和目标UID**。公开查询只读取身份仍为REVIEWED、版本一致且目标一致的名称。

- 撤回、重开、重新审核或改绑都会改变身份版本，旧名称立即退出后续请求的查询结果。
- 改绑不会把旧名称直接搬到新目标。重新审核后也不会自动恢复旧名称，必须另行核对并显式保存。
- 失效名称仍可在维护页查看；表单不会自动填入这些名称，避免原样复活。
- 不删除身份历史。名称替换的`NAMES`事件包含前后名称快照，与身份版本、名称行及既有操作日志在同一MySQL事务提交；审计失败全部回滚。

这里的“失效”针对**保存后发起的新请求**。已经打开的图谱或跨页名册仍需重新读取，当前没有浏览器推送。关系图谱的generation/evidence版本描述关系资料；名称断言另带身份版本，不把二者混作跨数据库事务。

## 缓存与失败处理

名称仅在控制器响应阶段批量附加，不写回Bangumi缓存、角色实体或世界观快照。来源缓存仍可复用，但每次响应重新查询当前名称。相关响应使用`Cache-Control: no-store`。

MySQL名称查询失败或超过名称投影边界时，保留原来源资料并返回`nameNotice`，页面提示当前已审核别名不可用。显式档案关键词检索在名称服务不可用时返回503，避免把失败表现为“没有结果”。名称按NFKC与不依赖环境的大小写规则生成检索键；规范化只用于检索，不改动原名称和实体编号。

单次投影最多1200个实体，按240个UID分组；每组超过4800条名称则整次不附加外站名称并提示。关键词对应超过1000个别名实体时要求缩小检索词，避免悄悄截断后给出不准确总数。各公开网络本身的角色/关系上限仍沿用既有规则。
