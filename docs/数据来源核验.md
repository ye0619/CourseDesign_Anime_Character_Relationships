## 字段映射

| 来源 | 内部字段 | 处理规则 |
|---|---|---|
| subject.id | Anime.sourceId | 转字符串；UID为anime:bangumi:{id} |
| subject.type | 动画筛选 | 当前样本为2；S05按官方定义只采动画条目 |
| subject.name/name_cn | name/nameCn | 原名必填，中文名可空 |
| subject.date/platform | airDate/year/format | 只从可解析真实日期推导年份，不补造日期 |
| subject.summary/images | summary/imageUrl | S05适配文本和展示图片地址，不下载图片 |
| subject persons[].id/relation | Person与PARTICIPATED_IN | relation保留原职务；roleCode使用版本化映射，未知职务保留原值 |
| subject persons[].type / actors[].type | 人员分类 | 2026-10-17确认列表直接携带type；仅type=1进入Person，组织条目排除计数，无需逐个补取详情 |
| subject characters[].id/relation | Character与APPEARS_IN | 角色按来源ID识别，不按名称合并 |
| subject characters[].actors[] | Person与VOICED | 此接口已限定作品，animeUid来自请求的subjectId，scopeKnown=true |

角色32（ちぃ）在作品12中的actors样本包含人员3862（田中理恵，type=1）。这条配音可以确定作品范围，不能推及角色在其他作品中的配音。

作品内配音接口可减少未知范围配音，但来源数据可能不完整。没有actors不等于确定没有声优。语言与配音版本在当前核验样本中未得到明确字段，保持空值，不推断日语或具体版本。

## 数据获取策略

- S05以显式作品ID清单为入口，先20—50部，不无限递归。
- 每个作品获取详情、制作关联和角色关联，再对需要的去重人物补充详情。
- 组织分类排除并记录。人员分类以官方定义进一步核验，未确认的记录不进入个人合作分析。
- 当前已实际看到组织type=2、个人type=1；这不代表只存在这两种来源枚举。
- 目前尚未获取作品间关系样本，RELATED_TO来源映射在S05核验；不得凭作品名称补造前传续作。
- 并发1、间隔不少于1秒、临时错误最多重试3次是项目保守初始配置，不是官方限流声明；收到429尊重Retry-After。
- 后续保留来源链接、获取时间、失败摘要，不把获取时间写成来源更新时间。

## 复现

在项目根目录运行`.\scripts\Verify-Bangumi.ps1 -SubjectId 12`可复现最小核验。S05使用`.\scripts\Fetch-Bangumi.ps1`读取固定20部作品的详情、制作和角色配音列表。响应缓存到data/raw/bangumi，缓存命中记录文件时间，新请求记录获取时间及URL；429尊重Retry-After，其余临时错误最多3次退避。
