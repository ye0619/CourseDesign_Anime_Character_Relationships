# 角色关系图谱（F08）

更新：2026-10-19。按用户新要求恢复图谱优化，参考成熟图谱实现改造角色图谱。页面 `/character-graph` 默认读取项目数据库；虚构演示可显式切换，数据库故障不会自动替换为演示数据。

## 分类与方向

角色分类分为三个独立层次：实体种类（角色、机体、舰船、组织）、作品内出场定位（主角、配角、闲角、客串）、角色之间的关联类型。

关联类型采用 [Bangumi 官方字典](https://github.com/bangumi/common/blob/master/person_relations.yml) 的28类。单一配置位于 `backend/src/main/resources/fixtures/character-relation-types.json`，后端校验、公开接口、前端筛选及后台新增表单共同使用。原有 TEAMMATE、MENTOR 继续兼容并标注旧数据，不计入28类。

| 整理分组 | 类别 |
|---|---|
| 身份及版本 | 形态、改编、原型、进化、前身 |
| 社交及情感 | 朋友、恋人、单恋、对手、配偶、前任 |
| 家庭 | 亲属、亲戚 |
| 组织及职能 | 成员、创始人、驾驶员、下属、上司 |
| 主从及饲养 | 主人、侍从、饲主、宠物 |
| 学习及工作 | 学生、老师、同事、同学、同门 |
| 补充 | 其他 |

分组为项目整理方式。方向统一为“起点相对终点具有该身份”：老师→学生、成员→组织、驾驶员→机体；单恋为倾慕者→倾慕对象。反向身份在侧栏转换显示，例如选中老师时展示其学生。无方向关系按端点UID排序存储。同一角色对的不同关系保留，连线使用不同曲率。

官方快照中的老师/学生等互逆记录规范化为一条老师边；其余互逆对同样处理，避免同一事实重复计数。剧透及已结束标记合并时取逻辑或，避免漏掉来源标记。原有人工维护字段和停用状态受导入器保护。

## 数据与中文名

来源为 [Bangumi 官方 Archive](https://github.com/bangumi/Archive) 2026-10-13快照，下载文件核对官方SHA256。仅流式读取 `character.jsonlines`、`person-relations.jsonlines`，保留已收录的933个角色；本机提取688个明确标注的简体中文名及983条按作品限定的关系，包含20种实际出现的类别。

仅在两个端点都在当前作品出场时投影该关系。它仍然是角色的全局关联，不能解释为这一季已发生的剧情。页面和关系出处均说明该边界，默认关闭剧透关系；已结束关系使用虚线并可筛除。没有收录连线的角色不自动推断朋友、同伴等身份。

中文名仅取来源原始Wiki中的“简体中文名”字段，跳过占位符及复杂未解析标记，保留原名、中文名来源链接和原始头像。缺少明确来源的名称保持原文。所有角色列表、详情及图谱已有的中文优先逻辑直接使用补充后的档案。

《葬送的芙莉莲》本机样本：91角色，55个有明确来源的中文名，13条关系，其中2条剧透；默认显示11条。已核对伏拉梅→芙莉莲→菲伦的老师方向，以及菲伦→修塔尔克的单恋方向。核验摘要见 `data/samples/bangumi-character-enrichment-verification.json`。

## 布局与交互

角色画布改用Cytoscape.js 3.34.4与fCoSE 2.2.0，版本固定在锁文件。其他通用图谱与统计图继续使用ECharts。

| 参考 | 本项目采用的做法 |
|---|---|
| [Cytoscape布局指南](https://blog.js.cytoscape.org/2020/05/11/layouts/) | 按阅读任务选择布局，使用成熟算法而非继续堆叠自制弹簧参数 |
| [fCoSE源码与示例](https://github.com/iVis-at-Bilkent/cytoscape.js-fcose) | 谱初始化、力导向优化和含标签的节点尺寸；完成后按含文字的边界紧凑摆放独立分量 |
| [Sigma邻域交互教程](https://www.sigmajs.org/get-started/add-interactivity/) | 选中角色后突出其直接邻居及关系，弱化无关元素；不将Sigma作为运行依赖 |
| [Cytoscape样式文档](https://js.cytoscape.org/#style) | 原生贝塞尔多重边、方向箭头、缩放层级文字、按需显示关系标签 |

- 疏朗网络：fCoSE负责关系布局，独立连通分量按画布长宽比紧凑摆放；不将连通分量宣称为算法识别的剧情社群。
- 环形总览：可切换Cytoscape原生环形布局。角色名册：使用可滚动的中文名/头像卡片，主角优先，避免91个角色被缩成不可读小点。
- 节点颜色表示出场定位，大小按直接关联的不同角色数计算；多条关系不重复增加该人数。机体/舰船和组织使用不同形状。
- 默认关系文字收起，悬停或选中角色时突出相关连线及文字；可手动显示全部关系文字。小网络保留可读名称，大网络采用缩放层级和索引检索。
- 选择、筛选及一跳聚焦保留已有坐标；选择只改变强调和镜头。主动切换布局、重新布局或重置会重新计算；fCoSE不承诺每次随机初始化坐标完全相同。
- 侧栏与画布均可选择角色，支持取消选择、只看直接关系、查看详情、缩放、平移、适应画布、重新布局及保存当前视图PNG。手机详情入口可滚动到具体档案。
- 默认隐藏暂无连线角色，未收录任何关系时仍可浏览角色；保留28类筛选、出场定位、实体种类、剧透及已结束筛选、中文名/原名索引搜索和关系出处。
- 原生画布不向远端布局服务发送资料，依赖随前端构建分发；页面文本和详情按Vue文本渲染。

## 结合《关系图编辑思路.md》的后续改造

参考用户[关系图编辑思路](../关系图编辑思路.md)，保留当前Cytoscape/fCoSE引擎，采用文档中适合本项目的数据阅读方式：

| 文档中的参考项目 | 当前采用的内容 |
|---|---|
| [relation-graph](https://github.com/relation-graph/relation-graph) | 带头像与姓名的角色节点、可检索角色索引及节点详情；借鉴交互，不另外安装第二套图引擎 |
| [ONEPIECE-KG](https://github.com/mrbulb/ONEPIECE-KG) | 将网络分析放在图谱旁：直接关联人数排行、两角色最短联系和逐条关系证据 |
| [Neo4j官方电影示例](https://github.com/neo4j-examples/movies-java-spring-data-neo4j) | 通过稳定身份连接作品和人物，沿用本地作品/制作/配音范围，提供跨作品比较和人物制作网络入口 |

- 默认启用角色头像，可关闭；只接受已有Bangumi图片域名，加载失败保留定位色。定位色显示在节点边框，选中和路径强调使用独立边框色。
- 选中角色后适应其直接邻居范围，避免手机只看到角色而看不到连线另一端；仍不更改节点坐标。
- “关系分析”可展开。排行按不同直接邻居数，不因同一角色对的多条关系重复计数；连通分量只说明已收录网络是否相连，不当作剧情社群发现。
- 路径使用当前可见网络的BFS最短路径，默认遵守有向边，允许明确取消方向限制；保留原始边标识，可点击步骤查看原始方向与出处。
- 统计和路径随类别、剧透、结束状态、定位、种类及聚焦筛选变化，加载结果截断时明确提示范围。不把路径等同于可传递的剧情身份。
- 单作品内关系与跨作品制作/声优关联分别保留入口，不把共同配音或共同制作误写成人物剧情关系。
- 浏览页新接入Bangumi在线资料与本地档案的组合探索，详见[探索作品数据融合](./探索作品数据融合.md)；在线看到作品不代表已经采集其人物图谱。

## 重建与更新

先准备已采集的 `data/normalized/bangumi-sample.json` 和作品角色原始缓存，再运行：

```powershell
.\scripts\Fetch-BangumiArchive.ps1
.\scripts\Import-Package.ps1 -Path data/normalized/bangumi-character-enrichment.json
node scripts/Verify-CharacterGraph.mjs
```

需要Python3.9或以上；仅使用标准库。下载、原始缓存及标准包位于已忽略的 `data/raw`、`data/normalized` 中。官方完整ZIP约425MiB，仅下载一次，后续命中缓存仍校验摘要。提取包经原有标准导入器写入，重复导入保持关系身份稳定。

## 接口与模型

`GET /api/v1/character-graph/works?dataSource=NEO4J` 最多返回50部作品；`GET /api/v1/character-graph?dataSource=NEO4J&animeUid=...&maxNodes=150` 返回角色及边。

maxNodes默认100，允许1—200；最多400条边，超限显式标记截断。筛选只针对已加载的有界图。停用实体、关系及无有效出场上下文的边不会返回；每条边的两端均在返回节点内。404表示作品不存在，400表示参数错误，503表示数据库不可用。

节点新增 originalName、imageUrl、characterType、nameCnSource；边新增 spoiler、ended、sourceUrl。relationTypes返回官方编号、名称、方向、反向类别、分组和兼容标记，完整契约见 `docs/接口契约.yaml`。

Neo4j边仍为 CHARACTER_RELATION，身份由来源、作品、类别与规范化两端组成，保存 evidence、sourceName、sourceUrl、sourceRelationId、spoiler、ended。此类边不参与制作合作统计，原有通用路径规则保持独立。

## 验证

最新前端24个测试通过，后端31个测试通过，类型检查及正式构建通过。图谱测试实际运行fCoSE，覆盖54角色中心网络的节点间距、反向/平行边、已结束标记、无悬空端点、孤立角色、坐标复用及分量边界不重叠；补充邻居去重排行、BFS路径、方向约束与过滤边界。

实际HTTP回归20部作品，688个来源中文名、983条关系，方向、范围、数量上限及演示兼容通过。浏览器核对《葬送的芙莉莲》默认14节点11边：选择芙莉莲突出3条关系，一跳聚焦为4节点3边，取消后恢复14节点11边且坐标不变；全部文字开关、环形布局、91角色名册及PNG生成通过。390px手机页面宽度390px，无横向溢出。

新交互实测：伏拉梅→芙莉莲→菲伦为2跳，突出3节点2条老师关系；反向按箭头查找无路径，明确取消方向限制后可查到反向联系。14个可见节点具有头像资料，排行首位芙莉莲直接关联3人；手机视口无横向溢出，选中的直接邻居均在画布内。

当前角色页构建包约594KB（gzip约183KB），按路由加载；构建有500KB体积提醒。此轮未做并发压测或大于后端200节点/400边上限的容量承诺。
