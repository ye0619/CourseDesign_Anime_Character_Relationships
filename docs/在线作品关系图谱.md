## 用户看到的流程

1. 在“我的片单”或“探索作品”打开任意公开的 Bangumi 动画作品。
2. 作品详情页直接显示在线关系图谱，也可进入 `/explore/anime/{id}/network` 单独探索。
3. 默认显示角色关系。后台读取作品的角色名册，再分批读取这些角色的关联角色；只绘制端点都在当前作品名册中的真实关系。
4. 点击角色，选中节点位于画布正中心，其他节点根据与它的距离重新分层排列。节点间原有连线保留，不创建“作品到所有人物”的中心星图。
5. 点击连线核对名称、方向、剧透/结束状态、来源备注及 Bangumi 角色页；搜索中文名或原名也可切换探索中心。
6. 切到“制作人员”，画布只包含实际制作人员和职务节点，连线标明承担的职务，不混入角色或声优扮演边。

本地档案页面的真实 Bangumi 动画也嵌入同一在线图谱。旧的带 Bangumi 动画编号的角色图谱/作品图谱入口会进入在线页面；虚构演示和本地档案网络保留。后者也分开角色、制作人员两个图层，配音边不再混合显示。

## 数据源与关系语义

使用 Bangumi 官方维护的[在线角色接口源码](https://github.com/bangumi/server-private/blob/master/routes/private/routes/character.ts)、[作品接口源码](https://github.com/bangumi/server-private/blob/master/routes/private/routes/subject.ts)和[关系类型词典](https://github.com/bangumi/common/blob/master/person_relations.yml)，通过固定来源读取：

- `GET https://next.bgm.tv/p1/subjects/{id}/characters?limit=60&offset=...`
- `GET https://next.bgm.tv/p1/subjects/{id}/staffs/persons?limit=60&offset=...`
- `GET https://next.bgm.tv/p1/characters/{id}/relations?limit=100&offset=0`

作品编号先由既有公开动画详情服务验证；网络服务不调用本地图库或持久化仓库，也不写入 MySQL/Neo4j。中文名使用在线接口的 `nameCN`，空缺时保留原名。图片仅接受 `https://lain.bgm.tv/`。

角色关联接口通常以关联角色相对页面角色的身份命名。老师/学生等互逆记录转换为同一语义方向及稳定边编号；单恋是单向关系，以页面角色为起点。成员、创始人、驾驶员在来源两端可能使用相同标签，本轮保留无向关联并合并反向重复，不将组织误画成某个人的“成员”。合并重复边时，剧透及结束标记采用保守的逻辑或。组织仍属于虚构角色实体，不等同于现实制作公司。

“同作出场”不生成朋友/同事等推测关系；人员与职务边表示实际分工，不声称人员之间存在上下级或私交。角色的全局关联可能涉及原作和其他季，页面明确提醒这一范围。

## 布局与组件分工

视觉沿用映间的鼠尾草绿，画布采用浅色留白：底色 `#fcfdf9`、正文 `#40594f`、角色绿 `#5a8879`、关系蓝 `#758aba`、亲属棕 `#b78a65`、选中金 `#d6a66a`。中文使用现有系统字体，作品名保留原名，减少装饰性标题。主要视觉是头像与带名称的关系线。

- 总览使用既有 Cytoscape/fCoSE 力导向及分量打包，保持角色之间的真实网络结构。
- 点击节点后使用真实邻接关系计算距离层，把选中节点置于 `(0,0)`；相机精确对齐节点中心。支持拖拽、平移、缩放、环形总览、返回全图、保存图片。
- 连线默认显示关系名称；缩放时调整字号，使手机上也能读到。画布默认桌面24节点、手机8节点，可增至48或全部已加载节点；完整已加载索引不受画布规模限制。
- `OnlineWorkNetwork.vue`：作品内的图谱类型、筛选、显示规模和选择协调。
- `useOnlineNetwork.ts`：独立拥有当前作品/类型的数据、分页、渐进加载、失败重试、取消和过期响应隔离。角色关系每批最多4个并发。
- `OnlineNetworkInspector.vue`：可搜索索引和关系/节点详情。
- `CharacterRelationCanvas.vue`：画布及其生命周期；通过显式属性开启点击居中，保持原演示功能兼容。
- `focusNetwork.ts`、`onlineNetwork.ts`：纯布局和边合并/作品范围投影，独立验证。
- `OnlineNetworkService`、`OnlineNetworkController`：在线资料转换和只读接口，不承接数据库导入逻辑。

本次实际使用项目安装的 `vue-best-practices`、`frontend-design`、`spring-boot` 技能；保持 Vue Composition API/TypeScript 与现有 Spring Boot 3.5 版本，不因技能示例升级框架。

## 接口、缓存与边界

本系统新增两个匿名只读接口，契约见 `接口契约.yaml` 0.9.1：

- `/api/v1/explore/anime/{id}/network?kind=CHARACTERS|STAFF&page=1..4`
- `/api/v1/explore/characters/{id}/relations`

每页60个角色/制作人员，最多加载4页，超出明确标记截断；单个角色一次最多读取100条关系。只加载当前名册，不递归抓取站外角色。前端最多保留5000条原始关系，超出显示截断状态。画布最多绘制400条边，优先选中节点/关系，超出明确提示；完整已加载索引仍可核对关系。来源有多少标注就展示多少，不保证每部作品都有完整图谱；无关系时提供在线名册，不造连线。

网络缓存5分钟，最多256个来源响应键，并合并同键在途请求；同时最多8个上游网络读取。暂时失败可使用30分钟内的旧响应，明确标记旧缓存；404移除旧响应并报错。与作品搜索/简介的60秒缓存独立。

路径、正整数编号、图谱类型、页码均校验；不接受任意远端 URL，不使用或转发观看账号的令牌、Cookie，不跟随重定向。连接5秒，公开读取从发起到响应体完成整体最多6秒（片单12秒），超时取消交换；响应体缓冲最多2MB，超限立即取消。个别角色失败时保留其余关系并显示未完成数量，提供单独重试；来源429时停止未开始的批次，保留部分结果并提示稍后显式重试，不自动继续请求；切换作品/类型时取消旧请求，旧响应不能覆盖当前图谱。
