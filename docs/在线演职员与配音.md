# 在线演职员与配音（P05a / P05b）

2026-10-20交付：在线作品的“作品关系与演职员”增加“配音与名册”，可在配音及出演记录、制作名单之间切换。按稳定人员ID归集多个角色/职务；同名不同ID保持分开，公司和组合保留来源类型。可检索人员/角色的显示名、原名、别名及职务，默认展示60个人员，另行展开已经加载的人员。

## 读取与覆盖

`GET /api/v1/explore/anime/{id}/credits?kind=CAST|STAFF&page=1`每次明确读取一类的一页，固定60个来源行、最多100页；没有自动全量抓取。`CAST.total`是角色名册行数，`STAFF.total`是制作名册行数，均不能当作人员数量。图谱原有240条/400画布边的限制不用于名册统计。

后端`SubjectMetadataService`标准化人物、角色、职务和饰演记录；`NetworkSourceCache`与原图谱共用公开原始页，保留同键在途合并、8个上游并发、256键LRU、5分钟新鲜期及失败时最多30分钟旧缓存。来源403/404撤销缓存并返回错误，不用旧资料掩盖权限变化或删除。个人账号、片单及观看状态不进入公共缓存。

每页提供`subjectUid`、`people/characters/staff/cast`、`coverage`、`source`和内容摘要`snapshotVersion`；名称使用P04a同一个解析器及规则版本。摘要包含适配版本、名称规则版本、来源路径和内容，不含每次读取的时间。

- 完整性记录实际返回/解析行、遗漏行/饰演记录、缺失casts字段、下一页、终页和上限。缺少casts与明确空数组不同；ID明确而名称等缺失的人员仍然保留。
- 单页只有第一页即终页且没有遗漏时才标`COMPLETE`，单独读取第五页即使已到终页仍为`PARTIAL`。
- 前端只在连续取得所有页、总数/适配和名称版本一致、无遗漏且没有过期缓存时显示“来源名册已加载完成”。这仅说明来源当前名单已经读完，不保证社区资料收录完整。
- 后续页失败保留已有页；CAST和STAFF分别保存页码、错误及重试。总数/规则变化拒绝拼接，并提示从第一页重读。切换作品或离开组件会取消未完成请求，晚到响应不能污染新作品。
- 跨页不是来源原子快照；相同总数下的内容变动无法仅凭分页接口排除。P08/P09消费时须继续说明来源时间和覆盖，不能用本功能直接声称完整个人报告。

例如后藤一里明确关联青山吉能（原声、语种未知）及邱涵菲/郭雅瑂（中配、中文）；花柳香子关联伊藤彩沙；芙莉莲关联种崎敦美（原声、语种未知）及李蝉妃/李昀晴（中配）。这些是社区来源记录，不为缺少版本/集数的记录补造发行版本。

浏览器实际加载《芙莉莲》第二页后，从60/91部分资料变为91/91来源名单已读完，人员按ID合并为130个实体。另读《孤独摇滚！》制作第五页返回44/284来源行，证明可读画布240条以后的名册；单独第五页仍标部分。

页面验证了角色名检索、语种/未知显示、画布卸载、第二页失败保留60个人员、配音与制作错误隔离和显式重试；切回制作图谱没有虚构角色节点。390px模拟视口文档宽375px，名册没有横向溢出；1440px合并分页也无溢出。仅为浏览器响应式检查，不代表真实手机硬件验收。无效kind、page=101及非数字页码均返回400；匿名公开读取正常，READY且两库UP。

证据：`data/samples/credits-source-checks.json`、`credits-acceptance.json`、`credits-source-328609.json`。可在隔离的本地开发页执行`scripts/Browser-CreditsAcceptance.js`，将原始检查JSON作为`sourceChecks`字符串参数传入；若浏览器工具把args解释为元素UID，直接将JSON作为函数实参表达式注入。脚本只在隔离页面模拟一个503响应，不修改后端、账号或远端资料，结束恢复fetch和原路由。
