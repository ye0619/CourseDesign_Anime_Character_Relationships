## 启动、交付与停止

1. 准备PowerShell7、JDK21—25、Node24及MySQL二进制。首次运行`./scripts/Initialize-Local.ps1`生成随机本机秘密；已有`.env`会被拒绝覆盖。前端先执行`npm ci`。
2. 开发运行：`./scripts/Start-Project.ps1 -JavaHome 'C:\Program Files\Java\jdk-23'`。脚本准备项目内Neo4j/JRE并启动独立MySQL、Neo4j、后端和前端；不注册系统服务。
3. 交付构建：`./scripts/Build-Delivery.ps1 -JavaHome 'C:\Program Files\Java\jdk-23'`。执行测试、契约/脚本/Compose静态校验、类型检查和构建，打包可执行JAR。摘要在`.local/delivery-manifest.json`，不含秘密。
4. 切换到交付模式：先`./scripts/Stop-Project.ps1`，再`./scripts/Start-Project.ps1 -Mode Release -SkipDatabases -JavaHome 'C:\Program Files\Java\jdk-23'`。后端使用JAR，前端使用构建预览。切换模式或重新构建后刷新浏览器，避免旧页面继续请求开发模块或旧资源。`SkipDatabases`要求数据库已经运行；从全停状态启动应省略它。
5. 默认停止：`./scripts/Stop-Project.ps1`只停应用。完整停止：加`-IncludeDatabases`，脚本先核对进程、实际数据目录及无活动同步/导入，再停止项目专用数据库；不会删除数据目录。使用Compose数据库时只使用默认停止，再执行`docker compose stop`保留卷。

默认地址：http://127.0.0.1:5173，后端8080、MySQL3307、Neo4j7687/7474，仅回环绑定。日志在`.local`。数据库密码及管理员凭据仅留本机，不复制到报告或截图。

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/v1/health/live
Invoke-RestMethod http://127.0.0.1:5173/api/v1/health/ready
```

live应为UP；ready应为READY且mysql、neo4j均UP。单库断连应返回503，恢复后200。首次启动校验Flyway V1—V3和Neo4j约束/校验和；重启不会重复导入样本或覆盖已有账号。首次在全新机器/空数据目录初始化仍需独立验收。

## 配置与排错

- `.env.example`包含数据库、后端端口、Cookie、Bangumi User-Agent、HTTP代理、只读来源地址和JDK示例。开发及交付预览的API代理都跟随`SERVER_PORT`。
- Windows后端启动器自动识别系统HTTP代理；其他情况下设置`BANGUMI_PROXY=http://主机:端口`。代理变更后重启后端，已有进程不会自动接收配置。本轮初始旧进程在线502，按启动器重启后恢复。
- `BANGUMI_API_BASE`和`BANGUMI_NETWORK_BASE`默认指向官方公开来源；只在本地故障验收时改为受控模拟源，不接收网页输入的任意URL。
- 端口被其他服务占用时，启动器拒绝将无法识别的页面当作本项目；停止器也会拒绝未确认归属的进程。
- 本机MySQL9.3存在Flyway版本支持提醒，实际迁移校验及查询通过。不能据此推定MySQL8.4容器已经验证。
- Stop-Project需要本机MySQL客户端及读取进程的权限；检查不能通过时停止并报错，不猜测归属。中文目录的ANSI字节和目录联接路径已在本轮实际停启中验证。

## 普通用户演示

1. 在`/library`关联自己的Bangumi用户名/UID/主页。公开关联明确标注未验证归属；可选Access Token只在服务会话内保存。同步完成前保留上一份片单，失败不清空。
2. 组合选择“已看”“8分及以上”“某标签/某发行年”，应用筛选；刷新、前进/返回后条件与页码应恢复，逐项移除筛选可见。
3. 打开`/preferences`，点击常见标签、评分、年份、形式或资料缺失统计，核对片单数量与统计一致；可切换个人/社区标签及校正评分。发行年不表示观看年。
4. 在`/anime`搜索“孤独摇滚”，进入未收录本地的328609详情，打开在线关系图；再搜索“葬送”进入400602，核对本地档案入口及在线图谱。来源失败时明确显示缓存或本地回退。
5. 图谱选择“角色关系”，检索并选择角色，核对其位于画布中心、关系文字、头像和来源；点关系查看方向、备注及来源。试验缩放、环形、返回全图和保存图片。
6. 切换“制作人员”，只出现人员与职务；加载更多，核对已加载/来源总数和240人上限提示。手机默认8节点，桌面24节点，完整已加载名册可检索。
7. 无已标注关系时显示名册，不把共现推断成关系。看大图时可先用小规模画布，再围绕一个节点核对，不要求240节点总览的所有文字同时可读。

本轮真实样本为《孤独摇滚！》33角色、《葬送的芙莉莲》91角色和《航海王》1051角色（按上限分批读取）。真实资料仅读取小样本和正常浏览；并发与故障测试均为本地来源。

## Docker

当前Compose仅包含两数据库，后端/前端在宿主机启动。先停止同端口的独立实例，初始化`.env`，执行`node scripts/Check-Deployment.mjs`。具备Docker的机器再执行`docker compose config --quiet`、`docker compose up -d --wait`，然后启动`Start-Project.ps1 -Mode Release -SkipDatabases`。确认ready、迁移和持久化后才可记为通过。不要分享包含密码的Compose配置展开输出，不要用删除卷来解决启动错误。

本轮无Docker，未执行容器运行、8.4迁移或卷持久化；静态校验不等于容器部署成功。

## 数据维护与边界

既有本地库20部作品、688个角色中文名、983条有来源的角色关联已保留。历史人工演示单独标识，不冒充真实剧情。标准包经维护接口幂等导入，个人片单不写入全局图。

旧管理维护、导入、用户管理及Verify-Business需要显式开启`LEGACY_ADMIN_ENABLED=true`并重启，普通使用保持false；不为演示启用后台或修改真实用户片单。跨MySQL/Neo4j不宣称原子事务；导入任务以稳定UID、逐记录结果和中断状态恢复。

剩余验证包括真实私有令牌、全新机器初始化、Docker、完整备份恢复及长时间内存/容量；详见[本轮验收与交付](本轮验收与交付.md)。
