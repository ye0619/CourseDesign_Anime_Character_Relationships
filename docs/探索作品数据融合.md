# 探索作品：Bangumi在线资料与本地关系档案

更新：2026-10-19。用户提出“探索作品应该是Bangumi实时获取和本地相结合”，本文件说明当前实现。

> 后续改造：任意公开动画的详情页现已直接显示在线角色/制作分工图，不再要求存在本地图谱。以下原有本地档案说明仅适用于本地资料区，在线图谱以[在线作品关系图谱](./在线作品关系图谱.md)为准。

## 浏览与详情

- `/anime`默认展示“在线 + 本地”。同一个搜索条件分别查询Bangumi公开动画条目和本地Neo4j档案；在线每页12部，本地每页6部，页码独立保存在网址中。
- 两区各自标注数量，不相加为去重后的全站总数。同一作品可能同时出现在两个分区；在线结果按稳定编号标记是否有本地图谱，而不是按名称模糊关联。
- 可切换仅在线、仅本地。仅本地模式不请求Bangumi，并保留Bangumi已导入、人工维护和合成演示的来源筛选。旧网址中的`source`条件自动作为本地模式处理。
- 在线独有作品通过`/explore/anime/{id}`打开简介、封面、发行日期、集数、社区评分和官方链接；同时直接解析在线关系，不需要先建立本地图谱。
- 已有本地资料时提供本地档案及角色图谱入口。在线最新简介与本地人工维护名称分别保留，不把在线返回值写入或覆盖Neo4j。
- 原有人员、角色档案仍以本地知识库为准；作品详情内的新图谱直接读取在线名册、角色关系和制作职务，不自动入库。

## 官方接口与筛选

依据[Bangumi公开接口契约](https://github.com/bangumi/api/blob/master/open-api/v0.yaml)：

- `POST /v0/search/subjects`：关键词、动画类型2、发行年区间及公共形式标签；查询请求经本项目的只读GET接口转发。
- `GET /v0/subjects/{id}`：动画详情；拒绝非动画条目及无效编号。
- 在线形式采用公共标签匹配，本地采用档案的形式字段，界面说明两者口径；不将一页结果再次过滤后伪造总数。
- 公开探索不使用用户Bangumi令牌，不转发用户Cookie，也不需要本地登录。

“在线获取”表示向官方接口请求资料，不代表所有资料变更即时可见。官方接口本身可能缓存；搜索接口被官方标记为实验性，格式变化时明确报告来源不可用。

## 缓存、故障与边界

- 应用内存缓存60秒，最多128个查询/详情键；页面显示获取时间和缓存状态。服务重启即清空，不新增数据库表。
- 来源超时、限流或临时失败时，有10分钟内的旧快照则返回STALE并告知；超过10分钟不继续拿旧数据冒充在线结果。404不会复用旧快照。
- 同时最多6个在线请求，连接超时5秒、探索请求总时限6秒，响应体最多2MB，不跟随重定向。请求路径为服务端白名单，不接受任意远端URL。
- 在线不可用时仍返回可用本地档案；本地不可用时仍可浏览在线资料，未能核对本地是否收录的作品明确标记“待核对”。
- 新增本地核对查询仅使用`Entity:Anime`、参数化UID列表和`LIMIT 12`。实际EXPLAIN显示`NodeUniqueIndexSeek`，沿用Neo4j5.26/Cypher5，不套用技能中面向Cypher25的不兼容语法。
- 开发代理等待时限20秒，容纳本地查询及上游超时后的明确反馈；切换条件会取消旧请求，旧响应不会覆盖新结果。

## 代码职责与技能使用

- `BangumiClient`复用已有代理、User-Agent及响应限额，增加固定动画搜索/详情请求；不混入片单令牌。
- `BangumiAnimeService`负责公开资料映射、并发限额与短时缓存；`ExploreService`协调本地查询、编号核对及来源状态；`ExploreController`提供只读接口。
- `ExploreAnimePage`组合搜索、来源反馈与两区分页；`ExploreAnimeDetailPage`展示在线详情及可用本地入口；`useExploreRequest`独立持有取消、重试和错误状态。
- 使用项目安装的`vue-best-practices`及其四份核心参考，采用Composition API、TypeScript、派生状态与清理请求；使用`frontend-design`保持现有作品/档案视觉语境，通过清楚的来源区分代替装饰。
- 使用`spring-boot`的分层、构造器注入、输入验证和测试做法；使用`neo4j-cypher-skill`的模式核对、参数化、上限及EXPLAIN做法。技能按现有Spring Boot3.5与Neo4j5.26适配，不因技能示例升级整个工程。
